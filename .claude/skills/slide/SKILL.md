# slide

You turn the user's material into ONE slide: profile the content, let `tools/compose.py` pick the composition, fill the spec skeleton, build, check, fix. You never position shapes yourself. Dense is the default (archive: ~180 words, ~63% of the body covered, 0-2 empty regions).

## Workflow

1. **Read everything the user gave**: data, text, research. Excel: `"excel": {"file", "sheet", "range"}` inside a chart / table / waterfall instead of typing numbers (first row = series names, first column = categories).
2. **Write the content profile** (JSON; example `examples/profiles/orbital.json`):
   `message` (the headline idea), `lang`, `items` [{`id`, `kind`, `points`, `series`, `words`, `label`}], `relations` [{`from`, `to`, `type`}], `insights` (N), `decisions` (N).
   - kinds: `bridge` `trend` `composition` `ranking` `comparison` `distribution` `correlation` `kpi` `geo` `process` `matrix` `lookup_table` `list` `text`, plus:
     `breakdown` (parts that sum to a total, e.g. CAPEX = a+b+c; `points` = leaves, `groups` = `[3,3]` leaves per sub-total -> `flow` panel with "+" junctions; same for `composition` + `hierarchy: true` or `parts: [...]`),
     `assumptions` (list of assumptions with their origin/source; `points` = rows, `series` = columns -> table with pill cells + `pill_legend`; also `lookup_table`/`list` + `sourced: true`).
   - optional item flags: `br_states`, `qualitative`, `share`, `numeric`, `titled`; on a `trend`: `phases: N` (named phases of the time axis -> chart `phases`), `signed: true` (negative then positive -> column), `payback: true` (adds a `note` link). Example `examples/profiles/coldchain.json`.
   - relations: `leads_to` `compares` `sums_to` `explains` `located_in` `zooms_into`.
   - recommendations / decisions: count them in `decisions: N` only; do NOT also add them as a `list` item (compose adds the cards panel itself; a list item double-counts them and can hide the `sections` options).
3. **Read the archive grammar** once per conversation: `brain/30-patterns/README.md` and its notes (MCP `slide_grammar()`): how archive slides combine sections, widths, headers, intros, what stacks in a section, grey boxes, dividers and connectors, with frequencies from 120 labelled slides. Use it to choose and fill the composition (e.g. what goes under a chart, which section gets grey); it describes habits, not layouts to copy.
   **Get options**: MCP `suggest_composition(profile)` or `py -3 tools/compose.py profile.json`. It returns `density`, `density_message` (pt/en), and up to 3 `options` (fewer when layouts fail the fit check) (layout, panels, links, why, a complete `spec` skeleton, 1-3 archive `examples`).
   It also returns `nearest`: the closest archive slides (deck, slide, structure summary, PNG path, or the command to export it) and the closest ready specs (`examples/`, approved `exemplars/`). Use them as a **check, not a template** (user ruling 2026-11-12, restating 2026-11-06: the archive is a library of elements and how they connect, not slides to copy): read 1-2 nearest PNGs to see how those elements are styled and connected, never to take over a whole layout.
4. **If `density` is "thin"**: tell the user FIRST, before anything else: "os dados podem deixar o slide menos denso que o normal para este tipo de caso". Then present the options that fit the amount of data (KPI strip, raw-numbers table, insight cards), then continue with the best one. Do not pad with invented content.
5. **Say the choice in one line**, naming why it fits the content (and an archive slide that uses the same element pairing, if any): "3 seções: mercado + praças, árvore de investimento, retorno; gráfico + tabela de premissas como no slide 19 do deck D03."
6. **Build from the recommender's skeleton** (its layout comes from your content's structure), not from an exemplar. Copy element *styling* from exemplars when useful (a tree's node styles, a table look, a growth arrow), never their layout. Retrieve-and-edit of a whole spec is only for an explicit "rebuild this archive slide" request. **Fill it** (replace every `TODO`):
   - `headline`: action title with a number, a full sentence, at most 190 chars. Never a topic label.
   - all data in the panels; do the arithmetic (shares, CAGR, totals) yourself and check it.
   - insights as bullets: `**bold lead-in:** claim with ==accent keyword==`. Only claims the data supports.
   - `source`: required. Never invent one; if none was given write "Dados ilustrativos" / "Illustrative data".
   - style: the user's default style (`my_styles`, see "Your own design") applies by itself when the spec has no `theme`: then do not set one. Otherwise ask only if the user did not say (`py -3 build.py --styles`; `theme` in the spec). Keep protected traits of the reference look (`bain_red`: Arial, red rules) unless asked to change. Fonts via `heading_font` / `font`; check that they are installed.
   - rich text works in headline, bullets, cells, callouts, cards: `**bold**`, `==accent==`, `//italic//`.
   - language: `lang` `pt` (default) or `en`.
7. **Build**: `py -3 build.py spec.json -o out/<name>.pptx` (or MCP `build_slide`). Fix "Spec invalid" errors. Read every density / overflow WARNING and fix it: fill empty cells, add content, grey panels only if the style uses them, or change layout / weights.
7b. **Make 3 variants** (different layout or element choice) and call MCP `rank_candidates(specs)` or `py -3 -I tools/rank.py a.json b.json c.json`. It builds each, measures it (structure distance to the nearest archive slide, metrics vs archive p10-p90, warnings) and orders them with a reason. It only orders: you pick the final one by looking at the renders. Render the top one and check it against the nearest archive image for density, hierarchy and element styling (not for the same layout).
8. **Render and check**: `powershell -NoProfile -File tools/preview.ps1 out/<name>.pptx`, read `out/<name>.png`. Check overlaps, overflow, title at most 2 lines, numbers match. Fix, rebuild.
8b. **One fix round** (overlaps, density, hierarchy, styling gaps you saw), then:
9. **Reply** with the .pptx path, the PNG and your assumptions (data you estimated, source placeholder, style).
10. **When the user approves the slide**, call `save_exemplar(spec, png_path, note)` (or `retrieve.save_exemplar`) so the library grows. `find_similar(profile_or_spec)` re-runs the retrieval.

## Your own design (colours, fonts, logo)

When the user wants their own look ("usa as cores do nosso clube", "copia o design destes slides", a logo, a .pptx/.pdf or screenshots of their slides):
1. **From a deck** (.pptx/.pdf): `py -3 tools/style_from_deck.py DECK --save NAME` (MCP `extract_style`). It reads the colours, fonts, title size/bold, corners and a logo repeated in a slide corner, and warns about fonts that are not installed or a missing logo.
2. **From words or screenshots**: read the colours as hex (and the fonts, if visible or named) and run `py -3 tools/style_from_deck.py --set NAME primary=HEX heading_font=... body_font=... [series=[4 hex dark->light]] [--logo FILE --logo-position footer-right|footer-left|top-right]` (MCP `add_style`). Every token is in `docs/styles.md`.
3. **Check it**: `py -3 build.py examples/composite_coldchain.pt.json -o out/style_NAME.pptx --theme NAME`, render it, and compare it with the user's slides (their PDF page or screenshot). Fix what differs (header look, footer rule, title size, corners, logo position/height) with `--set`. Two rounds at most, then show it.
4. Ask whether it should be the default for every slide: `py -3 tools/style_from_deck.py --default NAME`.
Styles are saved in `my_styles/` (local, not in git, survives updates). Never write user styles into `slidegen/themes.json`. If a font is missing, say so and offer Arial or another installed font. Copy only the user's own design (or one they have the right to use), never another team's logo.

## Hard rules (composite first, nothing dropped)

- **Composite is the default** for anything with 2+ data blocks (cost tree, chart, assumptions, KPIs, table). The fallback archetypes (`multi_chart`, `chart_takeaway`, ...) are only for ONE exhibit + prose; `build` warns "fallback archetype" otherwise. No mirrored symmetric halves.
- **Every data block the user gave must appear on the slide**: numbers, breakdowns, assumptions and their sources, KPIs (payback, IRR), phases. Do not drop one to save space; change layout / `cols` / weights instead.
- **Show where each part starts and ends** (user ruling 2026-11-11): on any slide with 3+ panels, group them into sections and mark them. Use `cols` column `title`s as section headers (`title_badge` 1, 2, 3 when the parts read in order), `divider: true` (dashed vertical line between columns), `dividers: true` (dashed horizontal line between stacked blocks), and `panel: "grey"` on 1-2 blocks that hold a different kind of content (results / KPIs, assumptions); never grey on every block. Check the render: a reader must see at a glance which block belongs to which part.
- **Dense, not crammed** (user ruling 2026-11-12): the *density and hierarchy* reference is exemplars 024, 029, 030, 031, 032 (how much text, which type size, header -> exhibit); their layouts differ and are not templates. For 4-6 blocks `compose.py` returns structurally different section options, ordered by the content (user ruling 2026-11-12): `band` (the main exhibit runs across the top in spec `band`, when it needs width: a bridge or a long series), `wide` (the main exhibit's section ~1.6x wider), `strip` (KPIs across the top, when they relate to no other block), `sections` (equal columns, as the archive mostly does); then the other section count. Pick by the content and say why; do not default to the same structure every time. Keep the skeleton's `section_style` (section header look drawn from the archive mix: `label` 36%, `centred_rule` 22%, `bar` 11%, `rule` 10%); grey goes on the section whose blocks the archive most often puts on grey; TODO section titles; a decision becomes a conclusion callout. Pick the variant that fits the content; put the insights in section titles, chart labels or the callout instead of adding bullets. In `cols`, panels fill the columns in order: column 1 rows top to bottom, then column 2, and so on, so reorder `panels` when you move a block to another section. Skeleton `links` are suggestions: delete the ones that do not carry a message. At most 3 sections; each = header + ONE main exhibit + at most ONE supporting element (big numbers, a small table, or 2 one-line bullets). An `intro` under a section header (12 pt, 1-2 lines, ~15 words) is optional (user ruling 2026-11-12; the archive uses one under ~9% of headers): add it only when the header and exhibit do not already say the section's point. Prose at 12 pt stays under ~110 words per slide (those exemplars: 68-107; a rejected test had 152); detail goes into tables (9-10 pt), chart labels or big numbers, not more bullets. No bullets under every chart, no long KPI labels, no extra panel per idea: drop invented support text before shrinking fonts. A column must still reach the bottom: when its blocks are short (big numbers + a few bullets), put them in one grey `frame` (`{"panels": [...], "style": "none"}`) and close with a `callout` conclusion, as in exemplar 006. A small supporting table under a chart uses the light look (spec `"table_header": "rule"`: bold header on a dark hairline, `rules: "rows"`, `row_h` ~0.34), plain text, no multi-colour pills.
- **Icons by default on short lists** (user ruling 2026-11-11): a bullets panel or cards/kpis with 2-5 short items (recommendations, drivers, KPIs) gets one icon per item (`icons` on bullets, `icon` on cards/kpis items; names via `find_icons` or `assets/icons/lucide/`). Pick an icon that names each item's point (award = chosen option, cpu = technology, clock = delivery time). At most one icon set per slide; long-text bullets stay plain.
- Do not restate the headline in panel banners: panel titles name the exhibit and its unit ("Fluxo de caixa anual, R$ mi"). Highlight the risk or message once (accent word in the headline, one filled flow node, a callout).
- Worked example: `examples/profiles/coldchain.json` -> `examples/composite_coldchain.pt.json` (flow cost tree + cash-flow columns with phases + assumptions table with origin pills + KPIs).

## Composite quick reference

Layouts `1` `2col` `3col` `4col` `T|B` `L|R2` `L2|R` `2x2` `2x3` `L|R3` `T|B3` `T2|B3` (up to 6 panels; use them for 5-6 items instead of trimming), and `cols` (free columns, each split into rows, with optional column `title` + `intro`; use it to follow an archive slide's arrangement exactly); chart kinds include `scatter` / `bubble` (points `{x,y,label,size}`, `quadrants`, `highlight`; use for correlations); chart `phases` (dashed phase dividers), doughnut/pie `callouts: true` (labels with leader lines), `legend_pos: "inside"`; spec field `logo` {file, position, height} (or a list of up to 3) puts logos in the footer / top-right; `tag` + `tag_style: "plain"` = small caps kicker above the title ("Anexos"); `title_size` (short big titles); panel `title_badge` (numbered circle before the panel title); `tracker.style` `nodes` / `boxes`; `chart_font` (slide-wide chart text size, archive slides are often 8-10 pt). Panels `chart` `table` `bullets` `cards` `kpis` `map_br` `process` `matrix` `flow` (boxes + connectors + "+"/× operator circles, for cost trees and calculation logic). Panel extras: `icon` on kpis/cards items and `icons` on bullets (Lucide names, `find_icons`); table cells `{"pill", "color"}` and `{"icon", "text"}` plus `pill_legend`; table styling (up to 10 columns; `head_fill` one colour or one per column, `col_fill` per column, `bands`, `grid`; cells `{"text", "fill", "bold", "box"}` to tint, bold or dash-box one figure; colours are hex or `grey`/`grey_dark`/`grey_mid`/`pale`/`primary`/`dark`, example `examples/composite_tables.pt.json`); `side_label` (vertical tab strip); `scale` (gradient bar with markers). Links `arrow` `bracket` `highlight` `callout` `xref` `cagr` `connector` (elbow arrow bar → table row) `note` (dotted free callout box). Maps are not drawn by the tool (user makes them externally). Emphasis shapes (optional, native, add contrast like the archive boxes/triangles): spec `emphasis` `backdrop` (grey/pale box behind the key panel or a "so-what" band, `y` [from,to]), `pointer` (triangle or `block` arrow in the gutter between two neighbouring panels), `accent_bar`; panel `title_shape` pentagon/chevron (step headers for sequential panels); kpis item `delta` up/down. Use 1-3 per slide, on the panel that carries the message (one backdrop, one pointer toward the conclusion, step headers for process-like sequences, deltas on KPIs that moved); do not decorate every panel. Example `examples/composite_emphasis.pt.json`. Details: `docs/archetypes.md` (composite), `docs/styles.md`, `docs/element-library.md`, example `examples/composite_orbital.pt.json`.

## Field gotchas (seen in tests)

- A `bullets` panel takes `items`; `bullets` is the text list UNDER a chart/table/flow panel. `table_header` is a spec-level field (whole slide), not a panel field.
- Percent labels: either fractions with `"number_format": "0%"` (0.41 -> 41%) or plain numbers with a quoted literal `"0\"%\""` (41 -> 41%).
- A waterfall of reductions (total, levers, result): `total_first: true` with the levers as magnitudes (negatives are read as magnitudes too); the hanging bars and level lines follow.
- `Spec invalid` errors name the panel and field (`panels/3: 'items' is a required property`); fix that key, do not rewrite the panel.
- Build WARNINGs `section header ... needs 2 lines`, `table header ... breaks mid-word` and `category labels ... will overlap` come from the build's own fit check (user ruling 2026-11-12): fix each one (shorter text, `col_weights`, more width, `cat_size`) before showing the slide.
- Rating tables (alto/médio/baixo): pills in one brand colour = favourable, grey = neutral, dark = unfavourable, judged per criterion (a high cost or high risk is unfavourable); no red/yellow traffic lights. Section headers fit on one line; table headers must not break mid-word (shorter header or `col_weights`). Panel titles under a section header are `title_plain` (the skeleton sets it).
- compose.py writes its `why`/notes and TODO placeholders in Portuguese even for `lang: en`; the slide text you write follows `lang`.

## Fallback: the other 25 archetypes

Use one only when a single exhibit with a prose column is genuinely best. `list_archetypes` / `get_archetype` (MCP) or `docs/archetypes.md` and `examples/catalog.json`: `chart_takeaway` (trend/size), `multi_chart`, `waterfall`, `comparison_table`, `scorecard`, `kpi_tiles`, `process_steps`, `timeline`, `matrix_2x2`, `issue_tree`, `funnel`, `tile_map`, `data_table`, `scenarios`, and others. Spec fields follow the catalog entry (headline <= 190 chars, 2-4 insights, takeaway <= 160 chars, `source` required).

Rules: slides are native (real charts, real text). The user's decisions (colours, fonts, language) beat defaults.
